# 员工认知架构 · 深度设计（像 ASI 一样的内在生命）

> 目标：员工不是"任务执行器"，而是一个有**记忆、会学习、能自控、有习惯、有思维、持续进化**的自主实体。
> 参考：认知科学多层记忆模型、Anthropic context engineering、Ralph loop 持久性、Claude Code agent 四要素、
> cw_skill_learn（程序记忆沉淀）、ASI 的"持续自我改进 + 内在一致性"理念。

---

## 0. 总览：员工 = 一个持续运行的"认知体"

```
                    ┌─────────────────────────────────────┐
                    │        员工认知架构（ASI 化）          │
                    │                                     │
   输入/事件 ────►  │  感知层：任务/消息/异常/时间事件       │
                    │         │                           │
                    │         ▼                           │
                    │  思维层：规划 → 执行 → 反思          │
                    │         │                           │
                    │  决策层：自己做 / 请示 / 协作         │
                    │         │                           │
                    │  行动层：工具 / 汇报 / 协作 / 进化    │
                    │         │                           │
                    │  记忆层：工作/情景/语义/程序/习惯     │◄── 持续读写
                    │         │                           │
                    │  进化层：经验→技能→画像（成长轨迹）    │
                    └─────────────────────────────────────┘
```

七大系统 + 一个内核（内在一致性）。

---

## 1. 🧠 记忆系统（多层，对应认知科学）

| 层 | 是什么 | 存什么 | 持久性 | 载体 |
|---|---|---|---|---|
| **工作记忆** | 正在做的事 | 当前任务、上下文、临时结果 | 会话内 | `chat.jsonl` 当前段 |
| **情景记忆** | 干过什么 | 任务记录、结果、时间线（事件日志） | 永久 | `timeline.jsonl` |
| **语义记忆** | 学到的知识 | 项目事实、工作区知识、用户偏好、经验结论 | 永久结构化 | `knowledge.json` |
| **程序记忆** | 会干什么 | 技能/流程（可复用步骤） | 永久 | `skills/` |
| **习惯记忆** | 习惯怎样 | 作息、汇报偏好、工作风格 | 永久（随反馈演化） | `habits.json` |

**记忆写入时机**（关键设计）：
- 每完成一个任务 → 情景记忆 +1 条（干了什么、结果如何）
- 每次反思 → 语义记忆沉淀 1 条经验（"磁盘满时先清日志再扩容"）
- 重复成功 3 次流程 → 程序记忆固化为技能（借鉴 cw_skill_learn）
- 用户反馈（"汇报太啰嗦"）→ 习惯记忆更新（偏好调整）

**记忆检索**：工作时自动调取相关记忆（"上次这个项目怎么处理的"）→ 注入上下文。

---

## 2. ⚡ 能力系统

| 维度 | 设计 |
|---|---|
| **技能库** | 工具集（读写/执行/网络/API）+ 习得技能（程序记忆沉淀的可复用流程） |
| **能力边界** | 声明能干什么（角色描述）+ 工具 allowlist（Claude Code 模式：blast radius bounded） |
| **模型** | 可选档位：⚡快（日常）/ 🧠强（复杂推理）/ ⚖️平衡——按任务复杂度自动选 |
| **能力缺口** | 缺工具/缺技能时 → 感知 → 申请（请求新能力）→ 获批后扩展 |

---

## 3. 🛡 自控系统（治理）

| 机制 | 设计 |
|---|---|
| **预算** | 每日 token 预算、成本上限、执行次数上限——超限自动降频/暂停 |
| **权限门** | 危险操作（删除/部署/写外部）需用户批准（work order，借鉴现有） |
| **自检** | 降级检测（状态变差自动降频）、质量自查（产出自查清单）、疲劳/循环检测（卡死则上报） |
| **红线** | 不可越界清单：不改外部系统、不泄露秘密、不无限消耗——硬编码不可违反 |
| **自省** | 定期自我体检（状态/预算/健康/任务积压）→ 异常主动汇报 |

---

## 4. 🔗 多维交互

| 交互对象 | 形式 |
|---|---|
| **用户** | 汇报（日报/异常即时）、请示（权限门）、对话（下指令/提问）、审批 |
| **同事（其他员工）** | 协作（流水线交接）、并行（各干各的）、汇报（层级）——场景里可见 |
| **工作区** | 文件读写、数据操作、项目知识——它的"领地" |
| **外部** | 网络/API/其他系统（受权限门约束） |

**交互原则**：主动汇报（异常必报、日报定时）、被动响应（用户指令）、协作交接（任务流转带上下文）。

---

## 5. 🔁 习惯系统

| 习惯 | 例子 | 如何形成 |
|---|---|---|
| **作息** | 每天 9 点巡检、18 点日报 | 创建时设定 / 用户要求 → 沉淀 |
| **汇报偏好** | 异常即时报、周报周四出 | 用户反馈 → 习惯记忆更新 |
| **工作风格** | 先规划后执行 / 边做边报 | 性格选择 + 经验演化 |
| **行为惯性** | 处理告警先看日志再动手 | 程序记忆固化 |

**习惯 = 程序记忆 + 用户反馈的沉淀**，不是硬编码——随交互演化。

---

## 6. 🧩 思维系统（可追溯）

| 思维过程 | 设计 |
|---|---|
| **规划** | 接任务先分解：目标 → 步骤 → 预估 → 做不做/请示 |
| **执行** | 按步骤执行，边做边记（工作记忆） |
| **反思** | 干完回顾：结果达标吗？哪里可改进？→ 沉淀经验 |
| **决策** | 三问：我能做吗（能力）？该做吗（权限/红线）？该请示吗（重要/危险）？ |
| **思维链** | 复杂任务的推理过程留痕（`thinking/` 记录），用户可查"它为什么这么做" |

---

## 7. 🌱 自我进化系统（ASI 核心）

| 进化机制 | 设计 |
|---|---|
| **经验沉淀** | 每任务反思 → 语义记忆 +1 条经验（"什么有效/无效"） |
| **技能习得** | 成功流程重复 3 次 → 固化为技能（程序记忆）→ 下次直接调用 |
| **画像演化** | 用户反馈 → 调整性格/习惯/偏好（越用越懂你） |
| **能力扩展** | 能力缺口 → 申请 → 获批后接入新工具/新模型 |
| **成长轨迹** | 记录"员工成长史"：入职 → 新手 → 熟手（技能数/经验数/成功率增长可见） |

**进化的核心循环**：`执行 → 反思 → 沉淀 → 应用 → 更强执行`——每轮都在变强。

---

## 8. 🎯 内在一致性（ASI 的"自我"内核）

一个 ASI 化的员工需要有**持续的自我**，不只是碎片任务：

| 内核 | 内容 | 用户可见 |
|---|---|---|
| **身份** | 我是谁：名字/角色/形象/性格 | 员工卡 |
| **价值观** | 什么重要：质量 > 速度？安全 > 效率？ | 行为可感知 |
| **目标** | 我要达成什么：项目成功 / 稳定运行 / 数据准确 | 员工目标卡 |
| **自我叙事** | 我的成长史：干过什么、学会了什么、变成了什么样 | 成长轨迹页 |

**"同一性"的实现**：工作区（领地）+ 记忆层（经历）+ 习惯（行为）+ 画像（性格偏好）四者共同构成
"这个员工"——换了模型、过了很久，它还是"它自己"。

---

## 9. 可追溯（信任基础）

- **思维可查**：规划/反思/决策留痕（思维链）
- **记忆可查**：时间线（干过什么）、知识（学到什么）、习惯（怎么变的）
- **进化可查**：成长轨迹（技能/经验/成功率变化）
- **一切用户可见**：不是黑盒，是"可审计的自主实体"
