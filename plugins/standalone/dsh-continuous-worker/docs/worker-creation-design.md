# 员工创建流程 · 详细设计 v2（融合 Claude Code agents / Ralph loop / Workflow）

> 功能灵魂。参考成熟设计：Claude Code subagents（人格化 agent 四要素 + 编排模式）、
> Ralph loop（fresh session + workspace 持久 = 7×24 模式）、Workflow（多阶段编排 + 结构化结果）。
> 设计原则：**用户动机是"要一个 7×24 干活的点"，不是"创建员工"——流程任务驱动，员工是任务的化身。**

---

## 1. 核心洞察：员工 = 人格化的 Subagent

Claude Code 里一个 subagent = 一个 markdown 文件：`name / description / tools / model` + system prompt。
**我们的员工就是把这个"agent 定义"人格化**——它有自己的名字、像素形象、性格、工作区，但本质上是一个
带持久记忆（workspace）的常驻循环 agent。

| Claude Code subagent | 我们的员工 | 用户在创建时定制 |
|---|---|---|
| `name` | 名字 | ✅ 起名 |
| `description`（被派活的依据） | **角色描述**（技能关键词） | ✅ 任务→自动生成 |
| `tools`（能力范围） | 权限/工具集 | ✅ 权限开关 |
| `model` | 模型选择 | ✅ 可选模型 |
| system prompt | 性格/工作方式/语气 | ✅ 性格选择 |
| —（无持久记忆） | **workspace 工作区**（Ralph loop 模式） | ✅ 选目录 |

**关键机制（借鉴 subagent）**：员工被派什么活，取决于它的「角色描述」（description）。
用户说"帮我盯服务器"，系统匹配"运维"角色 → 生成描述「监控/告警/故障排查」→ 以后有这类任务自动派给它。

## 2. 创建流程（任务驱动，4 步引导）

```
① 说任务 → ② 推荐员工（角色画像）→ ③ 定制（就职档案）→ ④ 就位（进入场景）
```

### ① 说任务（用户动机入口）
- 入口文案：**「新建 7×24 任务点」**（不是"新建员工"——贴合用户心智）
- 用户一句话描述："帮我 7×24 盯着服务器，磁盘满或宕机就处理"
- 提供示例：盯服务器 / 自动测试 / 整理周报 / 跑实验 / 设计内容

### ② 推荐员工（系统生成画像）
- 系统解析任务关键词 → 推荐角色（运维/程序员/科学家/文员/设计师…）
- **自动生成「角色描述」**（这是灵魂）：展示给用户看，用户可改
  - 例：`运维工程师 · 负责 7×24 监控服务器（磁盘/内存/进程），异常自动处理并汇报，擅长 shell 脚本与日志分析`
- 用户可换角色（每个角色有预设：技能/形象/默认名）

### ③ 定制（就职档案——借鉴 subagent 四要素）
| 要素 | 定制项 |
|---|---|
| **身份** | 名字、像素形象（发型/衣服颜色） |
| **描述** | 角色描述（自动生成，可编辑）——决定接什么活 |
| **能力** | 权限（能否执行危险操作）、工具集（读取/执行/网络…） |
| **行为** | 性格（严谨/活泼/沉稳——影响语气与工作风格） |
| **领地** | 工作区（专属目录 = 持久记忆） |
| **资源** | 模型选择、每日 token 预算 |

- 实时预览：员工卡（形象 + 名字 + 角色 + 描述 + 性格）

### ④ 就位
- 员工出现在所选项目区的场景里（坐在工位，头肩像素小人）
- 显示"已就位"：工作区/权限/模型/预算 摘要
- **单员工默认就绪**；点「＋再添加员工」→ 走团队设计（见下）

## 3. 单员工 vs 多员工团队

### 单员工（默认）
- 一个项目区一个员工 = 这个项目的专属打工人，一岗到底
- 场景：员工 + 工位 + 任务角标
- 适用：盯服务器、每日报告等单一职责

### 多员工团队（项目复杂时）
- 同一项目区多个员工，各有工位/工作区/任务
- **创建时可选团队模板**（借鉴 workflow 编排模式）：

| 团队模板 | 编排模式 | 例子 |
|---|---|---|
| 🔗 **流水线** | Sequential（串行链） | 程序员写 → 测试员测 → 运维部署 |
| 🌐 **并行分工** | Parallel（并行独立） | A 盯服务器 + B 做报告 + C 整理数据 |
| 🎯 **角色并行** | Role-based（同任务多视角） | 同一代码：安全审查 + 性能审查 + 可维护性审查 |

- **每个员工在团队中的"岗位描述"自动生成**：流水线里"程序员：负责开发，产出交测试员"
- 单层深度（借鉴 Claude Code）：员工不无限创建员工，项目区编排团队

## 4. 员工独特性与关系

### 独特性（区分每个员工的 6 维）
| 维度 | 内容 | 用户可见 |
|---|---|---|
| 角色 | 运维/程序员/科学家/文员/设计师 | 形象 + 名字 |
| 描述 | 技能关键词（决定接什么活） | 员工卡显示 |
| 性格 | 严谨/活泼/沉稳（语气风格） | 员工卡显示 |
| 形象 | 发型/衣服/配色（独一无二） | 场景里可辨 |
| 领地 | 专属工作区目录 | 员工详情 |
| 关系 | 协作/汇报/独立 | 团队视图 |

### 关系（多员工）
- **协作**（流水线）：A 产出 → B 消费（场景里工位相邻 + 任务流转）
- **汇报**（层级）：主员工统筹，子员工干细分活
- **独立**（并行）：各管各的，互不干扰

### 关系在场景中的体现
- 工位位置暗示关系（流水线相邻、并行分散）
- 员工卡显示"关系标签"（协作/汇报/独立）
- （后续可选）协作连线/任务流转动画

## 5. 落地要点（接后端时）

1. **员工档案 = 结构化数据**（JSON）：`{name, role, description, persona, workspace, permissions, model, budget, team}`——对应 subagent 四要素 + workspace
2. **角色描述自动生成**：任务关键词 → 模板生成描述（可编辑）→ 存为员工 description
3. **员工 = 常驻循环**（Ralph loop 模式）：fresh session + workspace 持久，由 cw/schedule/heartbeat 驱动 7×24
4. **团队编排**：项目区 = orchestrator，按编排模式（sequential/parallel/role）派活给员工
5. **场景 = 项目区**：创建项目区时选场景大类（办公室/实验室/开发室/创作室/研究院），员工就位到场景
